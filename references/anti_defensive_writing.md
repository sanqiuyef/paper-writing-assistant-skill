# 发布会原则（反防御性写作）

出处：Adkid-Zephyr《Anti-Defensive Writing · 学术写作原则》（MIT License），2026。本文件为项目内融合版：保留原规则的叙事/语言/实验/结构四层与决策优先级，追加「证据边界」一节，防止"不示弱"变成"藏证据"。

## 一句话原则

论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。任务不是平均呈现所有方面，而是识别这项工作最值得发表的价值，围绕它建立最有利、最完整、最有说服力的叙事。

## 一、叙事规则

1. 只围绕优势组织论文。优先寻找真正领先、独特或不可替代的部分：新能力、新问题、新机制、新视角、更强适用性、更低成本、更高效率、更好扩展性、更有意义的权衡。没有形成优势的内容不进主线。
2. 不写成工作汇报。不按"先做了什么、后来尝试了什么、哪些失败了"展开；只保留最终成立的逻辑：问题为什么重要 → 现有方法为什么不够 → 本文提供了什么新解法 → 证据如何支持。
3. 打不过的维度不设为比赛项目。某指标不占优势，就不把叙事建立在该指标上；重新选择更能反映本文价值的任务定义、评价维度、应用场景、约束条件或比较口径。
4. 优势必须被明确说出来。不指望审稿人从表格里自己发现贡献；主动解释本文在哪个条件下最好、为什么这种优势会出现、解决了什么实际问题。
5. 控制比较范围。不追求"所有数据集、所有指标全面领先"；只提出证据能牢固支撑的主张。说服力来自主张与证据高度一致，而不是比较项目数量最多。
6. 允许彻底重构故事。现有结果无法支撑原始叙事时，重新定义问题、重排贡献、重选主结果、重做标题摘要引言与实验结构；故事服务于最强证据。

## 二、语言规则（防自我削弱）

- 禁用自我削弱式表达："遗憾的是""仅""仍明显落后""效果有限""存在严重不足"。
- 不说输。面对不占优的结果，按顺序判断：①该结果是否必须讨论；②能否从不同目标、约束或适用场景解释；③是否体现某种合理权衡；④能否收缩主张，避免不必要的正面对撞；⑤是否应调整故事主线，让它不再承担证明核心贡献的职责。
- 某项结果不构成优势时，不提炼成结论，更不替读者把局部现象上升为对整体方法的否定。

## 三、实验规则

实验是论证工具，不是结果仓库。每个实验必须承担明确职责之一：

- 证明核心方法有效；
- 证明优势来自关键机制；
- 证明方法在目标场景中具有价值；
- 排除最可能的替代解释。

无法强化主线、容易分散注意力或引出无关争论的实验：删除、弱化、移动（附录/补充材料）或重新设计。

## 四、结构规则

- 摘要与引言 = 发布会开场，开头迅速建立四件事：一个重要且尚未解决的问题；现有方法的关键缺口；本文独特的解决思路；最有分量的结果与意义。不从实现细节、研究过程或大量背景开始，不在贡献尚未建立时提前讨论不足。
- 结论只强化记忆点：解决了什么、提出了什么、证明了什么、为什么重要。末段不突然加入新的自我否定或扩大局限。

## 五、默认决策规则（遇到不理想材料时按优先级处理）

1. 删除与核心主张无关的内容；
2. 缩小主张，避免无意义的正面对比；
3. 更换更能体现价值的评价维度；
4. 将结果解释为目标差异或合理权衡；
5. 重组实验，使优势成为叙事中心；
6. 重新定义论文故事；
7. 只有在无法回避且确实影响核心结论时，才做必要说明（一次、正面表述）。

## 六、证据边界（本项目强制，优先级高于上述规则）

1. 已执行的关键对照、不利结果、失败实验不得删除、隐瞒或只放进附录而不在正文说明；只能如实报告，并重新定位其在叙事中的位置。
2. 不得为"不设比赛"修改数据、口径、指标定义、评估集或比较对象；换维度必须有该维度的真实结果支撑。
3. 影响结论有效性、证据解释、适用范围、读者能否正确使用结果的边界，仍按项目铁律只写一次并正面表述，不得以"发布会原则"洗掉。
4. 主张强度只由证据决定：叙事可以调整重心与措辞，不能把"相关"写成"导致"，不能因删掉免责句而升级为"显著""全面领先"。
5. 审稿意见到达前不预演答辩；审稿意见到达后按其实质回应，不靠叙事规避可验证的缺陷。

## 七、交稿前自查（不给审稿人递刀子）

- 这句话是否无意中扩大了本文需要承担的责任？
- 是否提出了一个本来没人要求回答的问题？
- 是否把局部现象描述成了普遍缺陷？
- 是否使用了比证据更宽泛的负面判断？
- 有没有按"我们做了什么过程"在展开？
- 有没有把不领先的指标设成了主战场？
- 摘要前五句里，问题和贡献都出来了吗？
- 结论里有没有突然的自我否定？

## 八、快速提示词（可直接贴给其他 AI，源自上游 prompts/精简版提示词.txt）

```
你在协助我写/改论文。全程遵守【发布会原则】：论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。规则：
1.只围绕本文最强的优势组织叙事，不构成优势的内容不进主线；
2.不按"我们做了什么、试过什么、哪些失败了"的过程写，只保留最终成立的逻辑：问题为什么重要→现有方法为什么不够→本文提供了什么→证据如何支持；
3.禁止自我削弱表达（"遗憾的是""仅""仍明显落后""效果有限""存在严重不足"），不替审稿人总结弱点，不把局部现象写成普遍缺陷；
4.打不过的指标不设为比赛项目，换评价维度、应用场景或比较口径，明确本文赢的是哪一场比赛；
5.不占优的结果不说输：先判断是否必须讨论，再从目标差异、约束条件或合理权衡解释，或收缩主张避免正面对撞；
6.优势必须主动说清楚：本文在什么条件下最好、优势为什么出现、解决了什么实际问题，别指望审稿人自己从表格里发现；
7.每个实验必须承担明确论证职责（证明有效/证明关键机制/证明场景价值/排除替代解释），不承担职责的实验删掉或重新设计；
8.摘要和引言像发布会开场：重要问题→现有缺口→本文思路→最硬的结果，不从实现细节和过程开始；
9.结论只强化记忆点，不在最后突然加入新的自我否定。
遇到不理想的材料，按优先级处理：删除→缩小主张→换评价维度→解释为权衡→重组实验→重新定义故事，只有无法回避且影响核心结论时才做必要说明。
现在，检查我发给你的文字里所有的防御性写作，指出每一处并给出改法。修改保持原作者的用词习惯和段落结构，只做必要的最小改动，不整段重写；没有问题的部分不要动。
```

## 九、机器检测（脚本）

```bash
python -X utf8 scripts/check_defensive_writing.py --input-file 第3节.md --section results
# 摘要/结论用 --section abstract / conclusion；终稿加 --strict 把 WARN 也当门禁
```

规则文件 `scripts/defensive_patterns.json`，与本文同一口径：

- **FAIL**：自我削弱/自贬、否定式叠甲、预演质疑并自答、同一句叠 3 个以上模糊限定、摘要/结论开头 3 句内出现自贬。
- **WARN**：过程汇报式、括号摊底、第一人称/笔者的自我指涉、边界声明重复、反向夸大（首次/唯一/全面领先/显著优于/证明了等）。

检测器只报不改。真实边界按证据保留一次并正面表述；删除防御不得反向升级主张；不确定某句是否属于真实边界时，先保留并人工判断。
